## Measured on a real song (2026-11-12)

Song `OneMoreLight-cover` (254 s, 84 BPM, 71 blocks, master -14 LUFS / limiter -1.5 dB), live chain on the master `backing` against the server build of the same song (CLI build 3 min 45 s, master -18.3 LUFS integrated, peak -3.3 dBFS), 48 kHz browser capture, same time window. The vocal is the owner's real recording.

| Measured | Live before (main, 2026-11-12) | Live after PR 592 | Server |
|---|---|---|---|
| 0-30 s short-term loudness | -6.1 LUFS, 6.4 clicks/min, hard-limited at -1 dBFS | -17.0 LUFS | -18.0 LUFS |
| whole song integrated | NaN output (silence) when the whole chain ran | -18.17 LUFS, mean level -0.01 dB, 0 clipped samples | -18.33 LUFS |
| master level, bars 8-58 s | +10 dB (after the curve fix only), +30 dB before | -0.4 dB (sd 0.85) | - |

Causes found and fixed (PR 592): a volume gain `auto(0s:0, 238s:0, 241s:-18)` was read as +48 dB (inner levels above 1000, then NaN) and each sequencer lane played the mix of all lanes instead of its own audio (`?role=laneN`).

## Second round (2026-11-13): the drift and the clicks

Same song and method, a realtime headless capture of the playback output (an AudioWorklet recorder, 128-frame exact, no main-thread tap), compared with the CLI build per block (`--block --out`) in 10 s windows; per-block checks run the live graph on the server's own input wav (offline context).

| Measured | Live before | Live after | Server |
|---|---|---|---|
| master integrated | -17.13 LUFS | -18.24 LUFS | -18.18 LUFS |
| master, 10 s windows live minus server | -0.5 to +5.7 dB (+1 to +5.7 dB from 180 s) | -0.26 to +0.32 dB | - |
| vocal-balance, windows from 180 s | +1.0 to +5.5 dB | within 0.1 dB | - |
| `opname-level` compressor, real vocal | +2.33 dB, error -9.6 dB | 0.00 dB, error -61.7 dB | - |
| `guitar-tone` filter | +2.7 dB, polarity inverted after the first fix | 0.01 dB, correct sign | - |
| `vocal-balance` mixer (gain -12.041) | -0.68 dB | 0.00 dB, exact | - |
| clicks, `normalize` as chain target, 250 s | not reproduced: 0 clicks, 0 worklet gaps, residual against the server -59.8 dB, also under 3 extra chains | same | 0 |

Causes found and fixed: (1) the compressor kept its envelope in floats; the server keeps it in whole 16-bit steps and divides with truncation, so after a loud passage the envelope stops about -12 dBFS and the compression is held (+2.3 dB on the vocal, offline port -31.9 to -74 dB). (2) `auto(...)` was joined in dB; the server joins the points by straight lines in the gain (halfway between 0 and -18 dB is -5 dB, not -9). (3) a source shorter than the longest one looped on its own length (160 s vocal in a 254 s song restarted at 160 s, which was the +1 to +5.7 dB late in the song); a short sound now ends in silence like on the server. (4) a mixer gain such as `-12.041` is not a number for the server (`int.TryParse`, lane stays at 0 dB); the live mixer and the offline mix now read whole numbers only. (5) the live filter: the server's pair of one-poles is a Q 0.5 section at 1.554 times (low) or 0.644 times (high) the cutoff, and unused stages are 0 dB peaking filters (an all-pass with Q 0 or less is a polarity flip in Chrome); the filter vector went from +4.9 to -28 dB.

Clicks: the earlier 11.8 clicks per minute could not be reproduced; the capture here is an AudioWorklet recorder (a ScriptProcessor tap on the main thread drops buffers under load and looks like clicks). Whole-song realtime run: 732 chunks, no gap. Small remainders: `piano-drift` (pan `lfo(...)`) has no live automation of the pan (about 0.25 dB), the chorus is -13 dB error but level-exact, the filter and chorus differ in phase from the server (one-pole against biquad).

Not measured yet (see the third round): windowed bars 1-39 (loop region), the offline "Build and play preview" of the whole song, per-strip live mixer levels beyond `vocal-balance`. The parity badge per block was measured in the third round.


## Third round (2026-11-13): pan lfo, chorus and filter phase

Same rig; the block checks run the live graph (an offline context, the same code the knobs move) on the server's own input wav of the block and compare with the server's output wav of that block (`ample build song --block X --out X.wav`, a copy of the project), whole song, 254 s, residual in dB below the server (more negative is closer). `spec-tests/parity/song-blocks-live.spec.ts` is the rig (it skips unless `SONG_CASES` / `BADGE_BLOCKS` is set).

| Block of the real song | Live before | Live after |
|---|---|---|
| `piano-drift` (pan `lfo(32, -4, 4)`) | -28.3 dB, level -0.28 dB (not automated) | -72.3 dB, level 0.00 dB |
| `piano-wobble` (chorus, depth 5.5 ms) | -13.8 dB | -69.5 dB |
| `guitar-tone` (filter, low pass 3000 Hz) | -12.5 dB | -54.4 dB |

Conformance vectors (0.4 s test signal, live graph against the server): chorus -11.2 to -58.3 dB, filter -28.0 to -61.5 dB, pan lfo -82.0 dB and pan auto -81.6 dB (new vectors `pan~lfo`, `pan~auto`; the offline "Build and play preview" ignored an automated pan, -14.3 and -12.6 dB, now -82.0 and -81.6 dB), plus `filter~highpass` -57.3, `filter~sweep` (cutoff wobble) -69.9, `filter~resonant` -89.4, `filter~slope24` -89.1, `chorus~deep` -59.7. Offline port: chorus -18.5 / -30.9 to -80.2 dB, flanger -18 to -73 dB. Knobs set at once on the first value: `volume` -52.5 to -77.4, `width` -61.2 to -83.4, `tremolo` -59.8 to -87.3, `pan` -71.9 to -84.5, `delay` -57.8 to -61.7 dB.

Causes found and fixed: (1) pan: the live pan only read a whole number, so `lfo(...)`, `auto(...)` and `env(...)` stayed at centre. It now plays the server's curve (`web/lib/live-pan-auto.mjs`): the Q15 gains of the pan table for every point (floor of sqrt(t / 64) * 32768, the stereo gains over the centre gain, at most 1), joined by straight lines in the gain (halfway between -32 and +32 is 0.5 and 0.5, not 0.707), counted from the start of the song (the live window adds its first bar), `lfo(period, low, high)` a triangle of points half a period apart starting at `low`, played from looping buffers that restart with the loop like the other LFOs. (2) chorus and flanger: the server keeps the depth and base in whole samples (5 ms at 44.1 kHz is 220 samples, not 220.5), the triangle as an integer 0..32767 with the delay moving by (t - 16384) / 16384 of the depth, the delay in 1/256 sample and never below 2 samples; the browser used 220.5 and a float triangle, half a sample of delay error that is -18 dB on a bright signal (the offline port was off by the same amount). Also, the server reads a depth, period and mix as a whole number: `5.5 ms` is 5, which is why the real chorus was at -13.8 dB (the live graph and the port now read "5.5" as 5). (3) filter: the server's plain filter is two equal one-pole stages with their zeros at z = 0; a Web Audio biquad has them at z = -1, so it is a sample late at the top (the best lag against the server was 1 sample, -48 dB, against -28 dB without). The plain filter (low or high pass, 12 dB, no resonance) now runs in an AudioWorklet (`ample-filter-pair`, core `web/lib/filter-pair-core.mjs`, the same maths as the offline port, the cutoff wobble comes in as the LFO wave on a second input); resonance, band pass, notch and slopes above 12 stay biquads (the server's state-variable filter is the same bilinear transform, -89 dB). The rest of the residual (-54 to -62 dB) is the 16-bit truncation of the server's integer state. (4) every knob smoothing started from the default value, so the first 50 ms of each graph were wrong (a chorus depth of 1 means 1 s of sweep while it settles, 600 cents of filter wobble): the first value of a parameter is now set at once.

Parity badge per block of the real song (live graph against the offline render, the badge word): before `piano-wobble` -22.2 dB approximate, `guitar-tone` -20.3 dB approximate, `opname-double` -30.3 dB approximate; after -61.0, -236.9 (the same worklet core as the render) and -61.8 dB, all exact. Still approximate: `guitar-echo` (delay 455 ms, feedback 22%, mix 18%) -28.6 dB. Blocks with an automated volume (`piano-entry`, `guitar-entry`, `guitar-soft-ending`, `instruments-guide-duck`) have no offline render to compare with ("Automated volume requires the server audio path"), so they get no badge number.

Still open: the live flanger (-0.1 dB against the server; a Web Audio feedback loop cannot be shorter than 128 samples, the flanger's delay is 3 ms = 132 samples with the sweep below 128), the live phaser (-10.2 dB, the all-pass stages), the live EQ (-18.4 dB) and PEQ (-6.6 dB), the limiter (-29.2 dB), `guitar-echo` -28.6 dB (to be looked at: the vector at -61.7 dB is fine, so it is the parameters of the song). Not measured: windowed bars 1-39 (needs the whole live chain with a loop region, not only the block graphs) and the offline "Build and play preview" of the whole song (the AI and MIDI sources of that song would have to be rendered in the browser), per-strip live mixer levels beyond `vocal-balance`.

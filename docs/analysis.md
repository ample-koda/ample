# Analysis

Status: built; it includes a project-scoped review of audio transcriptions. Analysis lives outside the core, in `Ample.Plugins`, and never changes a take.

## What is there

| Analyser | Result | Method | Tolerance measured on synthetic fixtures |
| --- | --- | --- | --- |
| `tempo` | BPM, confidence, beat grid | onset strength (positive energy change) and autocorrelation, shortest strong lag, parabolic refinement | within 1 BPM for clean click tracks from 70 to 180 BPM |
| `key` | key (tonic and mode), confidence, chroma, three candidates | chroma from an FFT and the Krumhansl-Kessler profiles | right key for the C major, E major and A minor chord sequences of the tests; the relative key is the usual confusion |
| `loudness` | integrated, momentary max, short-term max, loudness range, true peak | EBU R128 (ITU-R BS.1770-4 K-weighting, gates at -70 LUFS and -10 LU; range after EBU Tech 3342) | 0.3 LU for a steady sine; a range of two levels 15 LU apart is found within 2 LU |
| `spectrum` | centroid, 85 % roll-off, flatness, shares of four bands | averaged Hann-windowed FFT frames | a sine puts its centroid near its pitch; white noise has flatness above 0.5 |
| `pitch` | pitch contour every 10 ms with a confidence | **YIN** (difference function, cumulative mean normalisation, absolute threshold 0.15, parabolic interpolation) | within 10 cents for tones from 110 to 880 Hz, also with 20 cents of vibrato |
| `melody` | melody plan: notes (pitch, start and length in beats on a quarter-beat grid, bar) | segmentation of the pitch contour; the tempo comes from the option `{"tempo":BPM}`, else from the tempo analyser, else 120 | a synthesised five-note melody with a rest comes back as the same pitches on the same beats |

These tolerances are measured on **synthetic signals** only. Nothing is claimed for real recordings until they are measured on real songs. **pYIN** (a probabilistic layer over YIN that copes better with real voices) needs a library or a Python plugin; the choice for now is plain YIN, recorded here so that it can be replaced behind the same schema.

## Results, schemas and caching

- Every result must fit `spec/schema/analysis-<kind>.schema.json` (the same small schema subset as the other spec schemas); a result that does not is refused (AMP5343).
- `ample analyze <take> --with <analyser> [--options json]` stores the result in `.ample/analysis/<key>.json` and links it to the take in `.ample/analysis/index.json`. The key is a hash of the audio content, the analyser id, its version and the sorted options, so the same audio is analysed once, a new analyser version recomputes, and two takes with the same audio share a result. `ample analyze --list` lists the analysers.
- The results are **not** stored as take data: the take bank counts data that no take owns as orphans and would quarantine them. A take, its plan and its data are never touched.
- Analysers are pure: the same samples and options always give the same text (tested).

## The melody plan and re-sing

The melody analyser writes `{"schema":"ample-melody/1","tempo":T,"notes":[{"pitch":60,"start":0,"length":1,"bar":1,...}]}`. Stored as data with the role `melody` of a take and pinned with `freeze plan`, it reaches the plugin as the input `melody` (see [Controllability](controllability.md)); the engine records its data id in the plan. A test builds a plan from a synthesised melody and feeds it through `freeze plan` into the echo test plugin. What a real model does with it (a re-sing that keeps the notes) depends on the plugin and is not claimed.

## Analysis plugins (the contract)

A plugin of kind `analysis` lists the analyses it offers in `analyses` (its `blocks` may be empty) and answers the request `analyze` with `{ "jobDir", "analysis", "input": "in/audio.wav", "options" }` by `{ "result": { ... } }`. The host copies the take's audio into the job folder, checks the result against the schema and returns it (AMP5343, AMP5344). For file-producing analyses such as source separation, the response may also include `outputs: [{ "role": "vocals", "path": "out/vocals.wav" }]`; paths are relative to the private job folder and are rejected when missing, duplicated, outside the folder or oversized (AMP5272, AMP5274). `plugins/analysis-fake` exercises this contract with generated bytes. A real separation/transcription plugin is not bundled.

**Permission:** a plugin whose manifest needs the GPU or the network is never started unless the user says yes to the question the host asks (`--allow-gpu`, `--allow-network` on the command line; AMP5340 otherwise). The built-in analysers use neither.

## Not built

- The optional `analysis-local-transcription` plugin uses preinstalled Audio Separator and Basic Pitch packages, plus a user-selected, preinstalled separator model. Model weights and Python packages are not bundled or downloaded; network access is blocked. The compute-device choice defaults to GPU, with a CPU option, and GPU jobs require explicit permission. Configure its Python executable, complete local model folder and model filename in the transcription wizard's JSON options. See [plugins](plugins.md#local-audio-transcription). Real-model accuracy and runtime have not been measured here.
- The UI uploads at most 10 minutes/128 MiB, shows progress, synchronized stem playback, a 16-bit WAV waveform and up to 8 MiB of returned vocal pitch/model-activity metadata, and keeps results under `.ample/transcriptions/`.
- The review UI groups vocal pitch frames above a model-activity threshold into editable note estimates and can download them or import them as a MIDI source block. The local Basic Pitch adapter's displayed 0–1 value is the clamped note amplitude, not calibrated confidence or a probability. When the selected separator returns multiple accompaniment stems, the adapter estimates one MIDI artifact per stem and suggests an editable GM program from the stem label; it also emits a combined multitrack MIDI artifact for one-step import. A model that returns only a complete instrumental stem produces one backing estimate. Stem labels come from model filenames and are not instrument recognition. Drum stems are skipped by default because Basic Pitch does not map drum hits; the explicit `drumMode: "pitched"` option requests a rough pitched estimate, not a percussion map. Non-vocal MIDI artifacts can be downloaded or imported as MIDI source blocks. Raw vocal MIDI artifacts are download-only; vocal notes must be reviewed and accepted in the pitch lane before AMPLE imports them. Creating final instrument-block tracks from these estimates remains a user-reviewed conversion step.
- The quality rule Q007 (tempo and key fit between blocks) still reports "not run": wiring the analysers into the quality rules is the next step.
- No model weights are bundled, and pYIN is not implemented. The local model adapter reports estimates, not recovered ground truth.

# The web UI (as built)

Opening a song resets the Source editor's file binding and reloads it when visible; a hidden Source editor follows the active song when reopened. Song switching asks before discarding unapplied source text. The editor file picker and project browser share this guard (2026-10-10; browser acceptance pending). The last opened song is kept in the user's recent-project record, so F5 and a server restart reopen it even if the port changes. If that song was removed, Studio opens the first available song.

Block playback shows a pending loading indicator; click again or use Stop to cancel. Only the latest playback request may start after asynchronous loading/output initialization. Audio metadata loading times out after 15 seconds. The browser retains its token in tab session storage across F5. Media/event cookies are named per server port and token generation, so an old tab cannot overwrite a newer tab's cookie after restart. A genuinely stale session token still requires opening the new launch tab; authentication is not weakened (2026-10-10; runtime/browser acceptance pending).

The Assistant bottom panel uses its available height: heading/actions/search stay fixed and only the conversation list scrolls. In the AI task dialog, excess wheel movement at the Activity log or sample-list boundary scrolls the outer content. Its message composer places attachments above a full-width field, grows to three lines and then scrolls; Enter inserts a line break and Ctrl+Enter or Alt+Enter sends. When reviewing a completed proposal, Codex's written summary appears beneath the fixed tab row in Output, Changes and Checks; newest presented audio samples appear first (2026-10-16).

Folder tree expansion uses an open/closed folder icon in place of the arrow. The size slider changes between details and tiles directly, without a resistance zone. Audio waveforms carry an invisible accessible range input for direct mouse/touch scrubbing and keyboard arrow seeking. Playing detail rows expand their name cell to show a waveform and collapse on Stop or natural end. Tile width presets start at 240px and reach 540px; the default is 360px, constrained by available panel width. WAV peaks are supported; other audio formats retain the placeholder when server peaks are unavailable. These follow-up changes are source/syntax checked; browser/audio acceptance is pending (2026-10-10).

Project browser tiles are wide cards suited to audio names. Folder and file-type SVG icons appear in the tree, detailed list, tiles and picker. Audio tiles lazily load waveform peaks, with a patterned placeholder when unavailable. Hover or keyboard focus exposes Play/Stop, Loop and a seek slider; touch devices always show them. Preview uses the shared player and local playback volume, starts only on Play, and stops on card leave, folder/view/filter changes, bottom-tab navigation, dragging, page hiding or window blur. Scrubbing keeps playback alive during the pointer drag. Browser/audio acceptance remains pending (2026-10-10).

## Block status and local listening volume (2026-10-10)

The right title-bar dot is now a status control. Red `!` identifies a source/build error; amber `!` identifies a block skipped by an upstream error; blue pulses while building; filled green means newly rendered in the last build involving that block; outlined green means an existing take was reused. Grey means not built/out of date, with a dash when disabled. Status tooltips include the available error or build time. Clicking an error opens Log, selects Song log or Build log, follows upstream failure messages and scrolls/focuses the corresponding error row. Completed build/cache badges no longer occupy the block body; current step and detailed progress remain visible during a build, then disappear for each block as its result arrives. Semantic flags such as dynamic/baked remain separate.

Ordinary Play/Stop actions use icons; Build and play/Cancel build retain their explanatory labels. The small arrow beside Play opens Loop, whose toggle keeps the menu open. The volume icon opens a vertical 0–150% fader with a reset to 100%; moving away from baseline gives the icon an amber tint and a tooltip explicitly distinguishing listening volume from master volume. It is held in this tab's memory, resets on reload, and is never written into song settings, output files or render plans. Shared playback, proposal audio, loop playback, file/clip previews, A/B, transcription stems, recording auditions and live MIDI previews use the local gain. Shared source meters remain before this gain. Values above 100% amplify playback and can clip at the device; they do not modify the rendered waveform.

The default `studio-dark` theme is token-driven by `web/styles/tokens.css`. Shared element treatment lives in `skin.css`; Studio panels build on `studio.css`. Available themes are `studio-dark`, `light`, `high-contrast`, `auto` and `classic`; the selection is remembered in the browser. Custom graph and waveform drawing reads the same CSS tokens.

`ample serve` serves the web app at `/`. It looks like the clickable sketch on purpose: the sketch's CSS is the app's CSS, and the same regions, buttons and behaviours are used. What is real here that was a mock there: every change goes to the server as an edit of the song text, so the graph and the source are always the same document, and the history, the takes, the seeds and the audio are the real ones.

## What works

### Project exports (2026-10-10)

Right-click a project file and choose **Export** to download its original saved bytes. Audio files additionally offer **Export as → WAV / MP3 / FLAC**. Folder menus omit ordinary Export and expose only **Export as → ZIP**. ZIP includes nested files and empty directories without following links or entering private `.ample` directories. Project sources are never overwritten.

Converted and ZIP exports run as temporary jobs. The progress dialog shows the current step, elapsed time, and either compressed source bytes/files or converted audio seconds/output bytes. ZIP has a byte-based progress bar after file discovery; audio conversion uses an indeterminate bar with live timing/size updates rather than guessing a percentage. **Cancel export** stops compression or terminates only the job's own ffmpeg process and discards its temporary output. A completed job starts a browser download and offers Download again for 30 minutes. Conversion requires ffmpeg on PATH or `AMPLE_FFMPEG`; a missing encoder is reported in the dialog. WAV conversion uses 24-bit PCM; FLAC is lossless, MP3 uses ffmpeg's MP3 encoder. Export reads the saved project file, not unsaved source-editor text.
The source editor supports Ctrl+mouse-wheel font scaling from 8 to 24 px; the browser page does not zoom while the pointer is over the editor, and aligned gutters and diagnostic overlays follow the same size. Ctrl+Space and inline completion offer sequencer channel keys such as `pan`, filter project audio samples by the text typed after `sample=`, and complete project file or sample-folder parameters by substring within the file types accepted by their block. GM SoundFont fields also complete `pack:` with the MuseScore General alias.

## Effect properties and numeric input
Numeric fields keep typing and arrow-key editing; focusing a ranged field opens a small floating slider that closes on blur or Escape. Block properties use remembered, keyboard-navigable tabs. The six audio effects have compact cards with bypass, their existing template parameters and visual summaries; ▶ builds that block and plays its resulting take.

The Studio **Advanced** dialog uses the same journaled edit path. Its buttons in the canvas and block properties both recognize connected audio: they offer to build the upstream input until a take is available, then allow playback. EQ and filter show estimated frequency-response plots; the compressor transfer curve follows the integer engine's steady-state linear-amplitude law, while bounded waveform and gain-reduction analysis comes from its exact render; duck edits a 16-step pattern; distortion, delay and reverb show parameter-driven plots; mixer has four gain and pan strips. Other plots are guidance, not measurements of the integer engine. With a built upstream audio take, **Local preview** decodes a bounded 30-second bypass render (fetched and decoded once per take, then reused across control edits) and applies Web Audio graphs for EQ, filter, compressor, duck, distortion, delay, reverb, chorus and convolution; it is labeled approximate and updates after control edits. Chorus previews a triangle-LFO-modulated delay line (fixed 20 ms base delay, depth/period/mix matching the template) so the effect is audible, not just the dry input. Convolution uses the selected project or pack impulse response, with live mix, level, predelay, length and normalization; changing the IR replaces only the impulse response while the input and playback position continue. **Hear the real thing** uses the renderer for the exact effect preview. The server preview is bounded and cached in process memory, and never creates a take or changes project history. A playback analyser drives the Studio output meter when Web Audio is available; the shared waveform scrubber supports seeking and loop regions.

The denoise panel's **Preview** runs a bounded spectral denoise approximation in a browser worker, so audio playback stays responsive without waiting for a server render. It uses the selected noise profile and current reduction/sensitivity controls; **Compare / render** still offers the exact AMPLE effect preview. The bypass audio for the worker is fetched once per take and reused for every slider change (it never depends on this block's own parameters), and the preview position is read again right before the filtered audio swaps in, so a control edit no longer re-fetches over the network or jumps the playback position backward. The panel's **Optimize: auto / speed / memory** group is shown apart from the sound controls: it is an execution-policy parameter (`affectsOutput: false` in the template), so every choice renders the exact same cleaned audio and only trades the server render's time against its memory use on a long sound.

The **Project** bottom panel shows the project tree/list with search, filters and view choices. The view mode, tile size, sort and detail-column layout are saved in the shared project settings; the current folder and tree width remain remembered per project in this browser. The detailed list includes lazy **Used by** and **SHA-256** columns. Tile cards and the picker show lazy WAV waveforms, MIDI note-roll summaries, song tempo/block counts and lyric excerpts using bounded cached project-preview routes. Project and picker OS file drops share the duplicate dialog, including Keep both and Apply to all. The file picker reuses the project tree, reveals nested preselected paths, shows file references, accepts uploads with per-file byte progress and offers all four conflict choices with Apply to all, creates folders, and has context actions for rename/move and deletion (folders must be empty). Lists above 2000 entries render a fixed-height virtual window. Tree rows support arrow-key navigation, Left/Right expansion, double-click expansion, `/` search and Backspace to move up; file fields can clear their path and sampleset fields select folders. Internal project-file drags carry relative paths; OS file drops use the upload flow.

## Honest differences from the sketch
- **Groups live in the view, not in the song file.** The language has no inner graphs yet, so a group is stored in this browser per project. The source is never changed by grouping.
- Notes, scores and flags are also kept in the browser.
- There is no cache probe before a build, so blocks show "not built" until a build has run (the build itself uses the cache).
- Undo restores the song text before the gesture; it does not undo view changes.
- "Controls" shows the rules of the server (what is ignored, what breaks reproduction) instead of the sketch's expected melody/words/sound table, which was an expectation and not a measurement.
- Playback uses an audio element streaming from the server, not Web Audio: it never holds a whole take in memory, but it is not sample-accurate (the A/B players stay within 0.1 s of each other in the tests).
- Arrangement sections (`web/app/view-sections.js`, rules in `web/lib/view-sections.mjs`) are bands at the bottom of the ruler, read from and written to the `section` lines of the song's `view` block (`saveSections` in `store.js`, one undo step). A change of only the view block does not stop a running build.
- Arrangement gestures edit the source placement; the text remains authoritative. Other waveform/clip-content editing remains in the source and the relevant block editor.
- History: going to a revision that is not the tip of a line forks a line there first (the server only moves between lines).
- The history graph has no named checkpoints separate from revisions: a checkpoint is a revision of kind "checkpoint" with your name as its message.

## Files: the project panel, drag and drop, the switcher and the save menu (2026-10-08)
The **project panel** is the home of file management. Right-click on a folder, on an empty spot or on the **+** button: **Add ›** creates a song, timed lyrics (`lyrics/*.lrc`), chords (`chords/*.chordpro`), an empty MIDI clip (`assets/midi/*.mid`), a module, a sample folder, a text note or a folder, each with a valid skeleton, through the same code as `ample add <kind> <name>`; a new file opens in the editor that fits. Right-click on a file: **Use in song ›** adds a block that reads it (the block types come from the `accept` lists of the templates), **Point a block at it ›** changes the file parameter of a block that exists, **Open as text**, **Show where used**, **Rename**, **Move**, **Delete**.

The Project tab starts at the selected project root, with its files listed. Folder rows in the tree can be dragged into another folder; the move uses the same reference preview as the Move command and refuses moves into the source folder or its descendants.

In the file view, files are always listed before folders. The active sort column and direction are applied separately within each of those two groups, in tile and detail views.

With no block selected, the properties panel shows **Song properties**. Its **Seed override** is blank when the song follows the project master seed; entering a seed overrides it for that song, and clearing the field restores the project seed.

**Rename and move are a refactor.** The panel first lists every line of the songs and modules that names the path (also inside a voice map) and what it becomes; **Move** applies it, one journaled step. A song with unsaved changes stops the refactor until it is saved or reverted. **Advanced ›** has *Rename without refactor* and *Move without refactor*: only the file moves and references may break. On the command line: `ample mv <from> <to> [--no-refactor] [--dry-run]`.

**Drag and drop.** A file dragged from the panel (or from the operating system, which uploads it into `assets/<kind>` first) lights up where it can go: in the **source editor** the lines that take it (outlined) and the places between blocks (a line), the nearest one marked; a drop fills the path (a different existing path asks first, **Alt** replaces) or adds a block; one Ctrl+Z takes it back. **Insert file…** in the editor bar does the same from the keyboard. File fields in the properties and the studio panels light up and take the drop; a node that reads that kind of file takes it on its file parameter; an empty canvas makes a block. The targets come from the `accept` lists of the template parameters and from `web/lib/file-kinds.mjs` (extensions to kinds); the edit a drop makes is `web/lib/drop-targets.mjs`.

**The file switcher.** There is no list of files next to the source editor any more (removed 2026-10-21): open a file with the search box above the text (Ctrl+P), with **Recent ▾**, or from the Project panel at the bottom. The **Recent ▾** dropdown is visible beside the project name at the top-left of the canvas and in the Source header. It shows the current song and source file under **Open now**, then recently opened songs and editable text files; a dot marks a file with unsaved or recoverable changes. The full-screen recovery diff lists pending source drafts and song/module undo buffers. For each other buffer, choose to restore it when opened, use its saved version or decide later. Choosing a recent file uses the normal switch flow, including its unsaved-change or recovery prompt. The quick switcher above the text still supports **Ctrl+P** or click, typing a few letters, arrows and Enter; with no query, recent files come first.

**Moving and hidden names.** Drag a file or folder onto a folder (a tile, a row or a folder in the tree) to move it into it, or onto the path at the top of the panel to move it out of the folder you are in. It asks first, listing the lines in songs and modules that follow the move (the same as **Move…**). Names that start with a dot, such as `.git`, are left out of the panel, the tree and the file picker unless the **Hidden** chip is on. New folders come from the **+** menu (**New folder…**) and from **Add → Folder**.

**Uploading audio.** An uploaded MP3, Ogg or FLAC file also gets a WAV next to it (`song.mp3` gives `song.wav`; a name that exists gets `-2`), made by ffmpeg at the same sample rate as 16-bit PCM, because blocks play WAV files. A toast names the new file. FLAC is lossless; an MP3 or Ogg decodes to exactly what it sounds like, which means nothing is lost on top, but nothing that the encoder dropped comes back. Without ffmpeg the upload still works and the toast says the conversion was skipped (`AMPLE_FFMPEG` sets the path).

**Changes and saving.** The same control sits in the source editor, the lyrics editor, the piano roll and (as the menu only) next to **Save** at the top: a dot says **typing, not applied** (text in the source editor that is not applied), **changed** (the working copy differs from the saved file) or nothing (saved), the disk icon saves (**Ctrl+S** works everywhere; the editor applies what was typed first) and **▾** opens **Save as…** (a copy as a new song), **Revert changes**, **Export…**, **Render block to file…** (the take of the selected block as WAV or MP3 in a project folder, `renders/` by default), **Show in the project panel** and **Copy path**. The Source file list and quick switcher include only songs and editable text files, not audio assets; following an audio-file link selects the block that uses it instead.

## Patterns and sections (2026-10-08)
The step grid of a drums or guitar block has a **pattern chooser** (the main pattern, the named ones, New, Duplicate, Rename, Delete) and a **section strip** under it: one chip per section with its pattern, its bars (− and +), arrows to move it, a cross to remove it, and drag and drop to reorder; **+ section** adds one. Everything writes the `patterns` and `song` parameters of the block (see [Samples](samples.md)). The **Patterns view** (the *Patterns view* button in the panel, or the block menu) opens the same grid, chooser and strip full width, with the voice map below it for the samples of the lanes; an audio file dragged from the project panel onto a lane gives that voice the sample. The FL Studio-like workspace is the advanced **sequencer block**: [Sequencer](sequencer.md).

## Build, play and stop (2026-10-08)
The header has three controls. **Build** builds what is out of date (also unsaved changes; blocks that did not change are not rendered again) and does not play. **Play** plays the built song; when something is out of date, or nothing is built yet, it says **Build and play**, lists what is out of date in its tooltip, builds first and then plays. **Stop** is one button: it cancels a build that runs (the blocks that were ready are kept; press again to stop audio that plays), otherwise it stops the audio. **Loop** repeats the audio, and when bars are chosen on the arrangement ruler a **Play bars a-b** button plays only those. The line next to Stop says what plays (the song, a block, a project file). A disabled button says why in its tooltip (errors in the song, a read-only state, a build that runs).

Keys: **Space** plays or stops (not while typing or in a dialog), **Ctrl+B** builds (Ctrl+Enter applies the source editor). Blocks that failed in the last build show a red badge (`2 failed`) that opens the build log, and the log ends the build with a line that names them. The audio of the song is downloaded from the file menu (Download the song audio, WAV or MP3). A block whose take is out of date shows no player: its take is removed as soon as the block changes.

## Build errors in the code (2026-10-08)
A line of the build log that names a failed block (`sq: failed: AMP5380: ...`) is a link: click it and the Source view opens with that line in view. The line is **underlined in red** (and has a red dot in the gutter). The line is the parameter the message names (a missing file points at the `file` line), otherwise the header of the block. The same log line has a **Show block** button that goes to the block in the node editor instead (selected and in view). Hover the line for a tooltip with the code, the block and the full message in selectable text, with a **Copy message** button; move the pointer onto the tooltip to select. When you change that line the mark goes away; the next build puts it back if the problem is still there (a new build also clears every mark first). The same red line shows in the Source view when you open it later, for as long as the line is as it was when the build ran. Model: web/lib/build-errors.mjs.

## The sequencer workspace (2026-10-08)
A sequencer block has a full-screen workspace (the Open the sequencer button, or the block menu): the channel rack, pattern tabs with step grids and the piano roll, the playlist with clips and sections, and the lanes strip. See [Sequencer](sequencer.md).

## On a phone (mobile UI, 2026-10-20)
At 700 px wide or less (a coarse pointer up to 900 px for the dialogs) the page switches to a phone layout; one stylesheet (`web/styles/mobile.css`) and one script (`web/app/mobile.js`) hold it, the desktop elements stay in the page and the phone menus click them. Desktop layout and mouse behaviour are unchanged. How it feels on a real phone is owner-observed; the specs check the DOM and geometry only.
- **Header:** one row (Projects, Undo, Redo, the big play / Build and play button, Stop, a small status pill, a more menu with Build, Save, Checkpoint, Volume, Loop, panels, Guide, Help, About). Buttons are at least 44 px. At 360 px with the longest label (Build and play) the status pill gives way first.
- **Bottom navigation:** Arrangement, Branches, History, Project and More (Variants, Assistant, Log); a panel opens as a bottom sheet with a drag handle (drag to resize, swipe down or tap to close).
- **Canvas:** pinch = zoom, one finger = pan, long press = context menu (on a button or dot: its tooltip), tap a dot then another dot to connect, bigger dots, minimap on demand. A tap that Chromium moves from a dot to a neighbouring block button goes back to the dot.
- **Dialogs and panels (MUI05):** every dialog (ask and confirm dialogs, compare, the Studio, the Advanced piano roll, checkpoint, About, file picker, recorder, ...) is a full-screen page with a sticky Back bar (Back does what Esc does; the system Back button closes the top dialog), a scrollable body and safe-area padding; none is wider than the screen. The projects view was already a full page with its own Back button.
- **AMPLE Jam (Lite piano roll) on touch (MUI06):** a full-screen panel (its close button is the Back button), a toolbar with 44 px buttons that scrolls sideways, pinch zoom (spread sideways = time, spread up and down = rows), two fingers moving together scroll, one finger draws / moves / resizes / selects as the current tool, a Hand tool (touch layout only) scrolls with one finger also in the Grid view, a long press deletes a note (accents a Grid step), the neighbour strip scrolls sideways.
- **Tests:** `npx playwright test --project=phone` (390x844, touch) runs `spec-tests/parity/*.phone.spec.ts`; the pure gesture maths (`touch-gestures`, `sheet-drag`, `dialog-history`, `lite-touch`) has node tests in `web/lib/test`.
- **Bug fixed on the way:** a double tap on connector dots (tap-tap connecting) counted as a double click on the block and opened its source view, which hides the canvas (`#canvaswrap.bmode`); a double click on a dot no longer does that.

## Editors and managers (as built)
- **Views:** Blocks, Source, Library and Branch manager share the canvas area (`web/app/views.js`). The view switch stays above every view. A project that opens with errors starts in the source editor; the node editor is read-only (banner) until they are fixed.
- **Source editor** (`source.js`, `lsp.js`): a locally bundled CodeMirror 6 editor with AMPLE syntax highlighting, a gutter and diagnostic/build squiggles, driven by the real language server over `/lsp` (live diagnostics, Ctrl+Space completion, Ctrl+click definition, rename, format, fix all). Valid song text syncs to the working copy after a short pause; the Properties panel follows the block under the text cursor and edits either way update the other view. Properties are hidden with an explanation while the source has errors. Save makes a revision; Ctrl+Enter confirms the current buffer. Text files the song refers to (lyrics, chords, notes) and the generated `ample.lock` (read-only) open in the same editor.
- Unapplied edits in source files are kept as separate browser recovery drafts. Switching files can preserve a draft; after reload, opening that file offers its timestamp and size comparison, a full-window saved/recovered view, and explicit restore or continue-saved choices. Drafts stay in this browser and project; applying or reverting the file removes its draft.
- **Lyrics editor** (`lyrics.js`, `lyrics-model.js`): timed `[bar N] text` lines with live checks (empty line, order, long line), sort on apply, import and export of `.lrc`.
- **Plugin settings** (`pluginui.js`): generated from the manifest's schema, validated before it is stored in `.ample/plugin-settings.json`.
- **Library manager and mounts** (`libraryui.js`, side panel "Folders and links"): linked folders, assets, details, where used, ample.lock line, copy into project. Offline mounts are marked and never become write targets.
- **Projects** (`projects.js`): recent list with a health summary, new project, settings (black box budget, retention, default engine, master seed through the dangerous act), health (findings, black box chain, interrupted commands to restore or accept, backup age), backups, export and cleanup.
- **Dangerous acts** use one dialog (`dangerous.js`): dry run, impact, backup suggestion with "Make a backup now", typed words and a reason; the confirm call only works with the token of the dry run (tested through the API too).

## Number fields (properties panel)
Numeric parameters are **typed fields with the browser's small up and down arrows** (also ArrowUp and ArrowDown in the field); a value is committed on Enter, on leaving the field or on an arrow click, and goes through the same edit path as every other parameter. A parameter whose template says `number`, and the known ranged ones (swing 0 to 60, humanize 0 to 100, stagger 0 to 80, gain -24 to 12, steps, bars), get this field; a value that is not a number (like `derived` for a seed) stays a text field. A value outside the range is moved into it with a message, and an empty field goes back to the last value. Focusing a field with a range shows a floating slider for that same value; typing remains available. The pure part (ranges, reading what was typed) is `web/lib/numfield-model.js`.

Multiline text parameters open in a wide responsive dialog with a tall, vertically resizable editor. Soft wrapping keeps long lines readable while preserving explicit line breaks when applied.

## Progress of a block while it builds
While a build runs, a block that is busy keeps its size: its status tag names the step that is busy ("synthesis 13%"), a thin bar along its bottom edge shows the whole block, and while the pointer is on the block a panel opens below it (animated, floating over what is below) with every sub-step and its own 0 to 100 % (a step that is busy without a known end is striped). Blocks that wait for others say "waiting". A block shows its result as soon as it finishes, even when another block at the same level is still rendering; the toolbar counts results from the current build only. The build-log time estimate counts newly rendered blocks, not cache hits. The ACE-Step plugin reports `plan`, `synthesis` and `isolation`; ace-server only says running or done, so those bars move by an estimate and jump to the end when the step is done. The **Progress** button next to Map turns the bars off (remembered in this browser). A plugin reports progress with `ctx.progress(fraction, step, stepFraction)`; the engine passes it on as the event `build.block` (block, state, fraction, steps), at most ten times a second.

## Ctrl+click in the source editor
Hold Ctrl in the source editor and everything that can be clicked is underlined: the names of blocks (in a block header and in a `from` line) and the paths of project files (for example the value of `file`). Ctrl+click on a block name shows the block in the node editor; Ctrl+click on a file opens that file in the source editor (a song opens as the song). A file without source, such as audio, selects the block that uses it.

## Sample set hints

Below the sample kit or sample set chooser the properties panel shows what the chosen set has: "N layers on disk, engine plays M" (and the same for round robins), a "what you are missing" line (layers left on the source according to `set.json`, files the engine does not play yet) and a collapsible region table (voice, layers, round robins, what plays, loop). The text comes from `web/lib/setinfo.js` (tested in `web/lib/test/setinfo.test.mjs`) and the numbers from `GET /api/samples`. Sets without extra files show nothing new. Velocity, choke and gain fields follow later.
